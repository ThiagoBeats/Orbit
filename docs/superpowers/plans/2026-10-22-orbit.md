# Orbit: Plano de Implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Objetivo:** construir o Orbit, um programa Windows que organiza a documentação de projetos de clientes e de máquinas padrão: estrutura de pastas automática, controle de revisões, painel, visualizador, e-mail via Outlook e importação.

**Arquitetura:**
- Um pacote Python `orbit.core` concentra toda a regra de negócio: pastas, JSON, revisões, importação, e-mail, presença e conexão. Ele não depende de nada da interface.
- A interface é HTML/CSS/JS puro, rodando numa janela pywebview (WebView2). Ela conversa com o núcleo por uma única classe `Api` exposta ao JavaScript.
- Os arquivos (PDF e imagens) são servidos ao visualizador por um servidor HTTP local, restrito à pasta base.

**Tecnologias:** Python 3.12, pywebview 5.3.2, pywin32 308, pytest 8.3.3, PyInstaller 6.11.1, fonte Roboto (woff2 embutido).

**Spec:** [docs/superpowers/specs/2026-10-22-orbit-design.md](../specs/2026-10-22-orbit-design.md). Leia a spec inteira antes da primeira tarefa. Os rascunhos visuais aprovados estão em `.superpowers/brainstorm/379-1792683614/content/visual-v2.html` (tela) e `logo-orbit.html` (opção **C**).

## Restrições globais

- Interface 100% em português do Brasil.
- Durante o desenvolvimento roda com `python main.py`. O `.exe` só é gerado na última tarefa.
- **Nenhum arquivo do usuário é apagado ou sobrescrito, nunca.** A única exclusão permitida é desfazer uma cópia que o próprio Orbit acabou de fazer, dentro de uma transação que falhou.
- Os originais escolhidos para upload ou importação são **copiados**, nunca movidos.
- Padrão de nome, projeto: `<Tipo> - <Cliente> - <Projeto> - <DDMMAA> - Rev<NN>.<ext>`.
- Padrão de nome, máquina padrão: `<Tipo> - <Máquina> - <DDMMAA> - Rev<NN>.<ext>`.
- Pasta de projeto: `<código> - <nome>`. Pasta de máquina: `<nome>`. Cada pasta de tipo tem uma subpasta `Antigos`.
- Caracteres `\ / : * ? " < > |` viram `-`. O caminho completo de um arquivo fica com até 240 caracteres.
- Todo JSON tem `versao_formato` (= 1) e é gravado de forma atômica: arquivo temporário na mesma pasta + `os.replace`.
- Todo evento do histórico grava o usuário do Windows e o computador.
- Tipos padrão, nesta ordem: Diagrama Elétrico, Topologia de Rede, Memorial Descritivo, Layout de Painel, Planilha de Cargas, Consumo Pneumático, Manual de Operação, Descritivo Funcional, Lista de Tags.
- Status padrão: Em elaboração, Para aprovação, Aprovado, Liberado para fabricação, As Built.
- Visual:
  - fonte Roboto; cantos de 8 px (campos e botões), 12 px (cartões) e 16 px (popups);
  - tema escuro suave como padrão e tema claro suave como opção, com a paleta da spec §9;
  - sem animações além das transições de borda.
- O núcleo (`orbit/core`) não importa `webview` nem `win32com`, com uma exceção: `orbit/core/outlook.py` importa `win32com`, e só dentro da função.

## Foco de revisão

Situações que a spec implica, que uma pessoa vai encontrar no uso real e que precisam de teste próprio:

1. **Arquivo em uso ao arquivar** (PDF aberto no Acrobat ou rede instável): mover a revisão atual para `Antigos` falha com `PermissionError`. Esperado: tudo volta ao estado anterior, o JSON não muda e aparece a mensagem "arquivo em uso". Teste na Tarefa 5.
2. **Arquivo de origem dentro da própria pasta do Orbit** (o usuário arrasta o arquivo da revisão atual como base da nova). Esperado: funciona, porque as cópias são feitas antes da movimentação para `Antigos`. Teste na Tarefa 5.
3. **Nomes com acento, barra e muito longos** (`"A/B Automação Ltda"`, nome de projeto com 200 caracteres). Esperado: nome higienizado, acentos mantidos e caminho com até 240 caracteres. Testes nas Tarefas 1 e 4.
4. **Dois nomes que viram a mesma pasta** (`"A/B"` e `"A:B"` viram `"A-B"`). Esperado: erro claro, nada é sobrescrito. Teste na Tarefa 4.
5. **JSON corrompido ou ausente** (editado à mão ou apagado). Esperado: o programa não quebra. O container aparece na lista marcado com erro e os outros carregam normalmente. Teste na Tarefa 4.
